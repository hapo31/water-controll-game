# 流域拡張と表示安定性の検証

2026-10-04。Godot 4.7.2標準版、Windows、Compatibility描画、1360×860。描画計測機のGPUはNVIDIA GeForce RTX 4070 Ti。数値はこの環境での短時間実測であり、すべての環境や長時間の豪雨を保証するものではない。

## 実装した地形

固定256×256、山地の3支流、合流湖、蛇行する本流、低地の窪地、海。支流の上流端は各5セル、毎秒1.2ずつの流入。海は固定水面高0の表示と、水量を保持しない一方向の排水境界を分けて実装。海では盛土・掘削を禁止する。

初期地形が同一シードで一致すること、全支流と湖から海まで4近傍で水面高を上げずに到達できることを検証した。地形・水リセットの分離と、天候変更で地形や水が消えない仕様を維持した。

## 計算量と描画

| 条件 | 水計算1刻みの時間 |
|---|---:|
| 旧計算を256×256へそのまま拡張、平面上に水深0.5 | 348.4ms |
| 隣接ペアの更新へ変更した最初の試作、同じ平面 | 41.9ms |
| ちらつき修正後の流域、画面実行中の直近値 | 58.0ms |
| ちらつき修正後の流域、画面なしの安定性計測 | 67.7ms |

後半の行は地形と計測条件が異なるため、厳密な同条件の倍率比較には使わない。最終画面の10秒計測では平均150.5FPS、フレーム時間p95は28.15ms。実験時間は6.85秒進んだ。描画は滑らかに動くが、水計算は20Hzの実時間進行には届いていない。実験時計を確認しながら使う。水計算と表示を別スレッドにしており、FPSと水計算速度を混同しない。

メッシュはグリッドの交換時だけ構築し、盛土・掘削では表示テクスチャから頂点を動かす。メッシュの作り直しを長押しごとに行わない。海全セルへの個別ラベル描画も行わない。

## ちらつきの原因と修正

最初の試作では、隣接ペアの走査順を奇数tickと偶数tickで反転していた。水量保存は満たしていたものの、薄い水の分布が二つの状態を行き来した。加えて水深0.003を境に表示を突然オン・オフにしていたため、広範囲の点滅になった。

修正では、半刻みの往路と復路を同じtick内で完結させる対称走査を採用した。計算途中の状態を表示せず、薄い水と流向矢印の不透明度も連続的に変える。

同じ初期流域・豪雨で100tick進め、その後20tickを計測した結果：

| 指標 | 修正前 | 修正後 |
|---|---:|---:|
| 水深0.003の境界をまたぐセル数 / tick | 18,161.2 | 39.2 |
| 水深の増減が交互に反転するセル数 / tick | 41,840.55 | 0 |
| 湖内の1tick水深変化の最大値 | 0.23972 | 0.00358 |
| 水量収支誤差の絶対値 | 4.44e-10 | 2.89e-10 |

反転の計測条件は、連続する二つの水深変化量の積が-1e-6より小さいこと。表示境界をまたぐセル数の減少は約99.8%。修正後の39.2は雨により水域が拡大する際の変化も含み、点滅が39.2マス残ったという意味ではない。表示側には既に水深0.003の不連続なオン・オフ判定を残していない。

## 検証

- 水モデル77項目：閉鎖系の保存、非負性、同水位の静止、越水、蒸発、固定流入・排水、長い河道の毎秒1.2の通水、海の固定表示・一方向排水・台帳、流域接続、天候切替、水リセット、定常降雨での非振動。全件成功。
- 実画面：海の盛土・掘削拒否、地形編集でメッシュを再構築しないこと、海の選択情報、計算と表示の進行、水収支、海への排水と固定水面を確認。
- 長押し入力24項目：盛土・掘削、ドラッグ、押し続けたときの間隔、編集上限、UI・フォーカス・再生中の制約。全件成功。
- 天候・初期化UI16項目：三段階の雨、状態保持、雨演出、水だけの初期化、フルリセット。全件成功。
