# 構成とデータモデル

> この文書は固定流域の実験室と当時の未実装案の記録です。現在は [ゲームの構成](game-architecture.md) と [ゲーム仕様](game-specification.md) を参照してください。

## 方針と責務

Godot標準版、GDScript、Compatibility描画。セルごとのNodeは作らず、256×256の配列を使う。水計算は画面なしでも実行できる。実行画面では1本のワーカースレッドで水を計算し、メインスレッドで入力・描画・UIを処理する。

```text

scripts/
  main.gd                     入力、視点、スレッドの開始・完了・停止
  model/grid_state.gd         標高、水量、河道、湖、海、初期水量、流向
  model/fixed_map.gd          固定の山地・支流・湖・蛇行河川・海
  sim/water_simulator.gd      保存的な辺の移動、流入、排水、蒸発、台帳
  sim/rain_experiment.gd      天候、時計、初期化、表示状態の公開
  view/world_view.gd          投影、固定メッシュ、表示テクスチャ、選択
  view/water_surface.gdshader 地形、水面、流向の表示専用シェーダー
```

## データ

`i=x+y*width`、面積1。`GridState`はelevation・water・peak_depthを倍精度配列、river・lake・seaをバイト配列、flowをVector2配列で持つ。source_cellsは上流端15セル。initial_waterは水だけを初期化するときの復元値。sea_levelは0で固定。

`surface(i)`と`visible_depth(i)`は海だけ固定海面から計算し、それ以外は標高と実水量を使う。総水量のwaterには見かけの海水を格納しない。

## 更新とスレッドの所有権

`RainExperiment.grid`は描画用の確定状態、`solver.grid`は計算用の状態。PackedArrayのコピー時共有を利用し、書換え時には配列が分離する。ワーカーは計算側の配列と台帳だけを更新し、シーンツリーを触らない。

Mainはprepare_stepで地形と天候を確定させてからワーカーを開始し、完了後にjoinしてpublish_stepを呼ぶ。公開済み配列とsummaryだけをUIが読む。水計算の時間はスレッドの返り値として受け取る。天候変更・水リセット・フルリセット・停止の前は未完了の1刻みを完了させ、破棄や状態変更と競合しないようにする。終了時もワーカーをjoinする。

固定刻みは0.05実験秒。計算が遅れた場合に大量の追いつき計算でUIを塞がない。FPSと計算時間は別に表示し、描画FPSが高いことと実験時間が実時間に追いつくことを区別する。

## 表示と地形編集

斜め投影は `((x-y)*12, (x+y)*6 - 高さ*9)`。地形上面・側面・水面・流向をセル単位の描画順で1個のArrayMeshへまとめる。形状はグリッド交換時だけ構築し、盛土・掘削では作り直さない。

256×256のRGBA浮動小数テクスチャに、表示水深・流向X・流向Y・標高を格納する。地形上面と隣の高さを使う側面もシェーダーで移動させる。UV.xの負の整数部分は水上面1、水下面2、流向3、地形上面4、東側面の下端5、南側面の下端6。残りの成分はセル座標。通常の文字やハイライトには適用しない。

invalidate_stateはテクスチャを次の描画で更新する。invalidate_terrainも同じ軽い更新経路を使う。視点やラベルだけの再描画ではテクスチャを作り直さない。表示値は単精度だが、水量の倍精度データへ書き戻さない。

地形編集は停止中に1セル±0.5。長押しは0.15秒ごと。標高の範囲は-4〜40。海セルは両ツールとドラッグ操作から拒否する。水量は変更せず、水面は新しい地面の上に表示する。全体表示のズームはマップの寸法から計算する。

## 天候と初期化

天候変更は地形・水・時計・計測・再生状態を保持する。水の初期化は保存済みの初期水量を復元し、地形を再生成しない。地形の初期化は水・海・湖・時計・台帳・選択・雨演出を含めて復元し、豪雨選択・一時停止にする。カメラと編集ツールは維持する。

## 次段階で追加するモデル（未実装）

### PhaseController

`PREPARE → RAIN → REPORT → PREPARE`のみ。準備は6ターン、1ターンは2実験秒の自動進行を初期案とし、一時停止と手動送りを併設する。水は準備中にも固定tickで更新。集計中は時間を停止する。雨後の流下待ち時間はRAINの末尾に含め、独立した第4フェイズにはしない。

`faith_awarded`フラグで報酬の二重付与を防ぐ。次Waveでは水・地形・施設を保持し、最大水深・被害時間・そのWaveの入出水台帳だけをリセットする。残留水を新Waveの初期量とする。

### ConstructionSystem / StructureDefinition / BuildOrder

施設定義はResource化し、`kind, cost, build_turns, footprint, effect`を持つ。建設予約は`id, kind, anchor, occupied_cells, remaining_turns, state`。最初は作業員や経路を表現しない。

| 施設 | 初期費用案 | 必要ターン | 配置と効果 |
|---|---:|---:|---|
| 堤防 | 4神力 | 2 | 1セルの実効標高+1.5。線状配置は連続予約で行う |
| 貯水池 | 10神力 | 3 | 指定点中心3×3の地面を-1.5、下限-4。凹地の幾何学的容量が増える |
| ダム | 14神力 | 4 | 指定した河道を横断する辺に遮水境界を置く。堤頂まで貯め、低位放流口に小さな流量上限を持たせる |

ダムは「水を消すセル」にはしない。辺データ`crest_height, outlet_capacity`をWaterSimulatorの候補流量計算へ追加する。堤頂以下では低位放流分だけ、堤頂以上では越流分も渡す。全量は必ず隣接セルに移す。一般の自由形状ダムや水門制御は後回し。

予約時に神力消費。範囲外・重複予約・完成施設・保護対象・水深0.15超のセルは拒否。建設途中で水深超過なら進捗停止し、完成直前にも再検査。雨中は全建設停止。取消は未完成のみ全額返金を初期案とする。

天変地異は1セル±0.5、費用2神力。施設への重ね操作はPoCでは拒否し、原案の施設破壊は後の検討に残す。全費用・時間は未調整。

### FaithCalculator / ProtectedSite

対象は`id, kind, cells, tolerance_depth, tolerance_duration, faith_value`。最大水深だけでなく閾値を超えた累積時間も記録する。人間・動物・植物で許容水深を変える。初期案は各種1地点、各10神力。常に洪水が危険とは限らない植物の詳細生態は扱わない。

集計は「守れた対象」「各対象の最大水深・被害時間」「得た信仰」「次Waveに残る水量」。敗北画面や成長報酬は水の挙動を評価した後に決める。
