## 夏の開始時の初回移住

地形シード20261004、シナリオシード9876で、春の治水・雨を2ターン分すべて計算した。合計480水理秒、実処理時間約50.9秒で、1年目・夏・1 / 2の治水開始時に住民1人が移住した。判定に使う浸水観測は300水理秒、移住後の候補は238区画で、平坦さ条件も適用されている。水量収支の最大絶対誤差は約1.04×10^-10内部水量単位だった。

1ターン経過時には移住せず、通算2・6・10ターン経過後に移住することをルールテストで確認した。最初の家は通算10ターン経過後に初めて人口が増える。春の途中で保存・再開しても移住先とシナリオ乱数が一致し、画面でも夏の開始時の移住通知と家を確認した。

移住時期と平坦さ条件の変更前に、地形シード20261004、シナリオシード9876で、治水・雨を省略せずに8ターン分、合計1920水理秒を計算した。当時の初回移住に到達し、人口1人になった。

## 移住地の平坦さ

10×10マス内の高低差100cmちょうどは移住可能、100cmを超える土地は移住不可になることを確認した。内側の突起・窪み、区画全体の傾斜も判定に含める。平坦な高台は絶対標高によらず候補になり、浸水時間や川筋などの既存条件も引き続き適用する。

盛土・掘削直後のハイライト更新と、移住直前の再確認を検証した。保存済みの古い適地情報は再開時に更新され、既存住民、地形、水、神力、シナリオ乱数は保持された。初年度の実水理計算で保存した同じ地形を新条件で再判定すると、117区画の候補が残った。

平坦さのテスト22項目、ゲームルール87項目、画面テスト34項目が合格した。画面上の適地表示と条件の説明、移住、保存・再開も確認した。

## 速度と描画

スキップ中も地形・水・HUDが表示され、読み込み画面やモーダルが覆わないことを確認した。16倍速を目標とする設定で、実時間約0.666秒で10.4水理秒、約15.6倍速で進んだ。水のスナップショットと残り時間が更新され、数字を添えない早送り記号が0.9秒周期で点滅した。通常の治水と雨の演出では記号が消え、状態を公開し直しても点滅が続くことを確認した。早送り中の拡縮、地形変更・Space・Tabの無効化、残り49.6秒分をすべて計算して雨の演出で停止することも確認した。早送り開始時と処理中のPNGを目視確認した。

水量が両側とも0の辺の計算を省く軽量化を適用した。生成地形の流入、全域の雨、乾いた地形からの流下、途中の地形変更、海・排水、由来追跡を含む3ケース各120刻みを、独立した同一初期状態で変更前と比較した。水量・流向・最高水深・通過流量・流入元・辺の移動量・水量収支の4,320比較で数値が完全一致した。生成地形の200刻み計測では1刻み約5.00msから2.76msになった。既存の水理77項目とゲームルール87項目も合格した。

描画用の水状態は公開時に複製し、ワーカーが進んでも公開前の画面データが変わらないこと、公開すると新しい水状態に更新されることを画面テストで確認した。

画面を描画しながら4倍速で進めたところ、実時間2.5秒に約10.2水理秒進んだ。水理1刻みは約4.95ms。別の水理テストを並行実行していた際の初回地形生成は約45.7秒だった。

タイトル、フェイズ演出、プレイ画面、マス情報、雨、結果、移住後の家と適地をPNGへ出力して目視確認した。日本語の表示、マス情報の単位、橙色の適地、家の人数、北が右上の方位表示を確認した。操作欄をスクロール可能にして、情報が増えても下部の操作にアクセスできるようにした。

画面テストでは入力イベントをViewportへ流し、右クリックのポップアップと左クリックの盛土を確認した。雨音と効果音は生成済みのWAVストリームとして再生し、音声デバイスの初期化と雨音プレイヤーの再生状態を確認した。音質の聞き比べや音量のユーザー評価は未実施。

## 実行環境の備考と限界

制限された実行環境でGodotの設定保存先に書けなかったため、検証コマンド内の `APPDATA` と `LOCALAPPDATA` をGit対象外の `work/` 配下へ向けて実行した。通常起動の保存先は変更していない。実行環境から証明書ストアを読めない旨の警告は出たが、本PoCはネットワークを使用せず、検証結果への影響はなかった。

水害の発生頻度、神力の増減、長期の面白さの評価は今後のプレイテストで行う。実河川の精度や、防災予測への利用を検証したものではない。処理速度は環境によって変わり、低速な環境では水理時間が実時間より遅れる可能性がある。
