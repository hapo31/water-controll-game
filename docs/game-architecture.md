# ゲームPoCの構成

基準仕様は [game-specification.md](game-specification.md)。固定流域の実験室は `scenes/main.tscn` と `scripts/main.gd` に残す。F5の起動は `scenes/game.tscn`。

## 責務

| ファイル | 責務 |
|---|---|
| `scripts/gameplay.gd` | 入力、カメラ、ワーカーの開始と合流、画面・保存・音の接続 |
| `scripts/game/game_units.gd` | cm・cm³/sの換算と被害しきい値 |
| `scripts/game/terrain_generator.gd` | Perlin地形、山・流入点、実水理による3回の川掘り、生成進捗 |
| `scripts/game/game_session.gd` | フェイズ、時計、神力、イベント、地形変更、集計、ゲームオーバー |
| `scripts/game/development_system.gd` | 浸水時間、10×10の適地、3×4の家、人口成長 |
| `scripts/game/save_store.gd` | 検査、一時ファイルとバックアップによる保存 |
| `scripts/game/game_audio.gd` | 合成効果音、雨の環境音、消音 |
| `scripts/ui/game_hud.gd` | タイトル、進捗、操作、マス情報、演出、確認、結果 |
| `scripts/view/game_world_view.gd` | 家と適地の表示 |
| `scripts/model/grid_state.gd` | 既存の地形・水状態。流入元の集合と通過流量を追加 |
| `scripts/sim/water_simulator.gd` | 既存の保存的な水理計算。任意の由来追跡・流量測定を追加 |

## 状態とスレッド

水理計算は既存の0.05秒刻み、対称な共有辺の緩和を使う。旧実験室の数値単位は変更せず、ゲーム層だけで換算する。由来追跡と通過流量計測はオプションなので、実験室の水理挙動は変えない。

地形生成は専用Threadで行い、画面はMutexを介して進行度・処理名だけ読む。生成完了まで地形を描画しない。

ゲーム進行は別のThreadで複数刻みをまとめて計算する。通常は最大32刻み、スキップ中は最大16刻みで画面へ戻る。スキップ中も通常のHUDを表示し、完了した各バッチの水状態を公開して描画する。読み込み画面へ切り替えず、カメラはワーカーの処理中にも動かせる。フェイズ境界で残りの刻みを打ち切り、早送り状態を解除して演出・結果に入って止まる。倍速は刻みの回数に反映し、刻み幅を変えない。ワーカーを待つフレームの実時間も時計へ積算する。

スキップ中の時計は実時間×16で積算し、その分だけ水理刻みを実行する。通常の治水で選んだ速度によらず16倍速を目標とし、各バッチの刻み数は蓄積した水理時間と最大16刻みの小さい方を使う。CPUが追いつかない場合も計算を飛ばさず、処理できる速度で進める。

HUDの早送り記号は水理時計から独立した実時間で点滅させる。同じ早送り状態の公開では点滅時計をリセットしない。スキップ終了、演出・結果、タイトル・地形生成画面で記号を消す。

ワーカー動作中にはメインスレッドからライブのGameSessionを読まない。画面のGridStateは公開時にPacked配列を `duplicate()` で複製したスナップショットを使い、適地の配列と家の辞書も複製する。マス情報、地形変更、保存などはワーカーに合流してから行う。計算途中の水や集計途中の家を表示しない。

## 川筋

3つの流入元を1・2・4のビットで持つ。実際に水が共有辺を移動した時に、移動先へ元の集合を合併する。合流は3・5・6・7として表せる。生成の各回で、水が通った由来の履歴と各マスの最大通過流量を保持する。

各行・由来の組み合わせの最大通過流量を選び、同率をすべて中心にする。中心と岸の掘削量は1回の配列へまとめ、隣接中心による重複掘削を避ける。次の回は掘った地形で計測し直す。

## 発展の観測

移住は通算2ターン経過後の治水開始時を初回とし、以後4ターンごとに試みる。家の成長は各家の建築・前回成長から8ターン後に行う。

各水理刻みで1cm以上の浸水時間を加算する。雨の開始ごとに現観測を前観測へ移し、新しい計測を始める。治水開始時に直近2つを使うと、雨→治水→雨の300水理秒が対象になる。

治水開始時に完了した観測割合を確定して保存する。その後の地形変更で適地を再確認しても、準備中の乾いた時間を加えて過去の観測結果を薄めない。

10×10のすべてが浸水時間・占有などの条件を満たすかを積分画像（summed-area table）で判定し、候補ごとに100マスの最大標高と最小標高を調べる。高低差が100cmを超えた候補は除外する。四隅だけで判断しない。配置可能な区画を記録し、その和集合を橙色にする。区画と内部の3×4の位置を抽選する。家の建築後に再計算して重複配置を防ぐ。

地形変更時、移住の直前、GameSessionの復元時にも適地を再計算する。保存済みの候補とハイライトをそのまま採用せず、現在の地形と条件に合わせる。既存の家・人口・シナリオ乱数は維持する。

## 保存と拡張

Nodeを保存せず、辞書とPacked配列をバイナリVariantへシリアライズし、識別子・ハッシュ・長さを付ける。読み込みでオブジェクトのデシリアライズは許可しない。

水理台帳を保存して再開後の水量収支を維持する。結果フェイズと計算済み結果を保存するので、再開時に報酬を計算し直さない。シナリオ乱数のseedとstateを保存する。

`event_log` は雨・移住・集計をターンと水理時刻付きで記録する。`tutorial_state` は空の辞書として保存する。過去記録・チュートリアルの画面は未実装だが、このモデルへ接続できる。
